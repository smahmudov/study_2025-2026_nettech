# Цель работы

Изучение принципов распределения и настройки адресного пространства на устройствах сети.

# Теоретические сведения по работе

## Основные компоненты
- **GNS3** — среда моделирования сетей. Позволяет создавать виртуальные топологии с маршрутизаторами и коммутаторами.
- **FRRouting (FRR)** — маршрутизатор L3 с поддержкой OSPF, BGP, RIP, IS-IS.
- **VyOS** — сетевой дистрибутив Linux с CLI, предоставляет маршрутизацию, NAT, VPN.
- **VPCS** — виртуальные конечные устройства, используются для ping/trace.

## Адресация IPv4
- 32-битный адрес.
- Запись: `x.x.x.x`, где каждый октет — 0..255.
- Требует маски для деления на сеть/узлы.

Пример:
`172.16.20.0/24`  
`/24` → сеть, оставшиеся биты → хосты.

## Адресация IPv6
- 128-битный адрес.
- Формат: `xxxx:xxxx:xxxx:xxxx:....`
- Строится по принципу *префикс (Subnet ID) + Interface ID*.
- Автоконфигурация SLAAC (получение адреса от RA роутера).

Пример префикса:
`2001:db8:c0de::/48`

## Протокол ARP (IPv4)
Назначение:
- Определение **MAC-адреса** устройства по его IPv4.

Процесс:
1. Узел отправляет широковещательный запрос (ARP Request)
2. Получатель отвечает ARP Reply

Используется *только для IPv4*.

## ICMP / ICMPv6
- **ICMP (IPv4)** — контроль передачи данных, проверка доступности (ping).
- **ICMPv6** включает:
  - Neighbor Solicitation / Advertisement (аналог ARP)
  - Router Advertisement (автоназначение IPv6)

ICMPv6 заменяет ARP для IPv6.

## Двойной стек IPv4 / IPv6
Устройство может иметь **оба протокола одновременно**:
- IPv4 используется для традиционных сетей
- IPv6 — для современных и глобальных

Позволяет постепенный переход с IPv4 на IPv6.

## Разбиение IPv4-сети на подсети

#### Сеть **172.16.20.0/24**

- Префикс: `/24`  
- Маска: `255.255.255.0`  
- Broadcast: `172.16.20.255`  
- Диапазон узлов: `172.16.20.1 – 172.16.20.254`

- Число подсетей внутри данного блока без дальнейшего деления: `1`

2) `172.16.20.128/26` — 62 узла  
   - Диапазон: `172.16.20.129 – 172.16.20.190`

3) `172.16.20.192/26` — 62 узла

### Разбиение IPv6-сети на подсети

### Сеть **2001:db8:c0de::/48**

**Характеристики**
- Префикс: `/48`
- Маска (hex): `ffff:ffff:ffff:0000:0000:0000:0000:0000`
- Тип: documentation/global unicast (внутри `2001:db8::/32`)
- Диапазон адресов (краевые значения) всего блока `/48`:  
  от `2001:db8:c0de:0000::` до `2001:db8:c0de:ffff:ffff:ffff:ffff:ffff`  
  (в IPv6 нет broadcast-адреса)

**Разбиение на 2 подсети двумя способами**

**A. За счёт идентификатора подсети (Subnet ID)**  
Берём 1 бит из 16-битного поля Subnet ID (между /48 и /64) ⇒ получаем два равных блока `/49`:

1. `2001:db8:c0de:0000::/49`  
   диапазон: `2001:db8:c0de:0000::` – `2001:db8:c0de:7fff:ffff:ffff:ffff`
2. `2001:db8:c0de:8000::/49`  
   диапазон: `2001:db8:c0de:8000::` – `2001:db8:c0de:ffff:ffff:ffff:ffff`

Каждый `/49` содержит `2^15` подсетей `/64`.

**B. За счёт идентификатора интерфейса (Interface ID)**  
Выбираем любую подсеть `/64` внутри данного `/48` (например, `2001:db8:c0de:0::/64`) и делим её, «заходя» в 64-битное поле Interface ID ⇒ два блока `/65`:

1. `2001:db8:c0de:0::/65`  
   диапазон: `2001:db8:c0de:0::` – `2001:db8:c0de:0:7fff:ffff:ffff:ffff`
2. `2001:db8:c0de:0:8000::/65`  
   диапазон: `2001:db8:c0de:0:8000::` – `2001:db8:c0de:0:ffff:ffff:ffff:ffff`

### Сеть **2a02:6b8::/64**

**Характеристики**
- Префикс: `/64`
- Маска (hex): `ffff:ffff:ffff:ffff:0000:0000:0000:0000`
- Диапазон адресов (краевые значения) всего блока `/64`:  
  от `2a02:6b8::` до `2a02:6b8:0:0:ffff:ffff:ffff:ffff`

**Разбиение на 2 подсети двумя способами**

**A. За счёт идентификатора подсети (Subnet ID)**  
В блоке `/64` **нет** оставшихся битов Subnet ID (они уже все использованы к отметке `/64`).  
Разбить «по Subnet ID» невозможно, если у вас только `/64`. Теоретически, имея агрегат `/63`, получаем два `/64`:
- `2a02:6b8::/64` и `2a02:6b8:0:1::/64`.

**B. За счёт идентификатора интерфейса (Interface ID)**  
Делим имеющийся `/64`, используя старший бит Interface ID ⇒ два `/65`:

1. `2a02:6b8::/65`  
   диапазон: `2a02:6b8::` – `2a02:6b8:0:0:7fff:ffff:ffff:ffff`
2. `2a02:6b8:0:0:8000::/65`  
   диапазон: `2a02:6b8:0:0:8000::` – `2a02:6b8:0:0:ffff:ffff:ffff:ffff`

На конечных устройствах успешно настроены IPv4- и IPv6-адреса, проверена связность с использованием команд `ping` и `trace`.

Дополнительно проведён анализ сетевого трафика в **Wireshark**, что позволило визуально убедиться в корректной работе протоколов **ARP**, **ICMP** и **ICMPv6**, а также проследить процесс определения MAC-адресов и обмена эхо-запросами между устройствами. Полученные результаты подтверждают правильность построенной топологии и корректность настройки сетевой адресации.
