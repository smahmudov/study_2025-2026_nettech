# Цель работы

Получение навыков настройки службы DHCP на сетевом оборудовании для распределения адресов IPv4 и IPv6.

# Теоретические сведения

## Адресация в протоколе IPv6

Протокол IPv6 является преемником IPv4 и обеспечивает значительно расширенное адресное пространство. IPv6-адрес имеет длину 128 бит и записывается в виде восьми шестнадцатеричных блоков, разделённых двоеточиями. Адрес состоит из сетевого префикса и идентификатора интерфейса. За счёт большого адресного пространства исчезает необходимость в механизмах трансляции NAT, что упрощает архитектуру сети.

### Механизм SLAAC

SLAAC (Stateless Address Autoconfiguration) — это механизм автоматической IPv6-конфигурации узлов без использования DHCPv6. Узел получает префикс сети из сообщений Router Advertisement (RA), формирует идентификатор интерфейса и создаёт IPv6-адрес. Для определения соседей и проверки уникальности адреса используется ICMPv6 и процедура DAD (Duplicate Address Detection).

### Router Advertisement (RA)

Router Advertisement — это сообщения протокола ICMPv6, распространяемые маршрутизатором для уведомления узлов о параметрах сети. RA могут содержать:

- сетевой префикс;
- MTU;
- адреса маршрутизаторов;
- флаги **M** (managed) и **O** (other), определяющие способ получения настроек.

Назначение флагов:
- **M-flag**: указывает, что узлы должны использовать DHCPv6 Stateful для получения IPv6-адреса;
- **O-flag**: разрешает использовать DHCPv6 Stateless для получения только дополнительных параметров (DNS, домен).

## DHCPv6 Stateless

Stateless DHCPv6 используется совместно со SLAAC. В этом режиме адреса узлам не выдаются — они формируются самостоятельно на основе RA. DHCPv6 Stateless сообщает только дополнительные параметры:

- DNS-сервер;
- доменную зону поиска;
- время жизни записей.

Данный режим позволяет гибко использовать преимущества SLAAC, дополняя его конфигурационными возможностями DHCPv6.

## DHCPv6 Stateful

Stateful DHCPv6 является аналогом классического DHCPv4 и полностью управляет адресацией узлов. DHCPv6-сервер выделяет IPv6-адреса из пула, хранит информацию об аренде, отслеживает состояние и время жизни адресов. Узлы запрашивают адресацию через последовательность сообщений:

1. **Solicit** — поиск DHCPv6-сервера.
2. **Advertise** — сервер сообщает о готовности выделить адрес.
3. **Request** — запрос конкретного адреса.
4. **Reply** — подтверждение назначения IPv6-адреса.

Stateful DHCPv6 используется, когда требуется полный контроль над распределением адресов.

## Neighbor Discovery Protocol (NDP)

Протокол NDP заменяет ARP в IPv6-сетях. Он выполняет следующие функции:

- определение IPv6-адресов соседних устройств;
- обнаружение маршрутизаторов;
- поддержание таблицы соседей;
- проверка доступности узлов.

Основные типы сообщений NDP:
- Neighbor Solicitation (NS);
- Neighbor Advertisement (NA);
- Router Solicitation (RS);
- Router Advertisement (RA).

## ICMPv6

ICMPv6 является обязательной частью протокола IPv6 и выполняет множество критически важных функций:

- диагностика и проверка связности (аналог `ping`);
- поддержка SLAAC;
- работа NDP;
- уведомления об ошибках и перенаправлениях.

ICMPv6 сочетает в себе как служебные функции, так и механизмы конфигурации.

## Вывод

В ходе выполнения лабораторной работы в среде **GNS3** была развернута расширенная топология IPv6-сети, включающая три коммутатора, два клиентских узла и маршрутизатор **VyOS**, выполняющий функции шлюза. На маршрутизаторе последовательно реализованы оба режима работы DHCPv6 — **Stateless** и **Stateful**.

На этапе Stateless-конфигурации были настроены Router Advertisements с флагом *other-config-flag*, что позволило узлу PC2 автоматически сформировать IPv6-адрес посредством SLAAC и получить дополнительные параметры сети (DNS, доменное имя) через DHCPv6. Функциональность была подтверждена проверкой настроек интерфейса, таблицы маршрутов и файла resolv.conf, а также успешным обменом ICMPv6-эхосообщениями с маршрутизатором.

Stateful-конфигурация предоставила клиенту PC3 полноценный DHCPv6-адрес из заданного диапазона 2001::100–2001::199. Анализ вывода dhclient, проверка параметров интерфейса и таблицы маршрутов, а также просмотр активных аренд на маршрутизаторе подтвердили корректную работу протокола. Клиент получил глобальный адрес, DNS-сервер и доменную зону поиска от DHCPv6-сервера.

Дополнительно был выполнен анализ сетевого трафика в **Wireshark**, где удалось проследить полный цикл DHCPv6-обмена (Solicit → Advertise → Request → Reply) для Stateful-режима, а также взаимодействие по ICMPv6 и механизмы Neighbor Discovery. Полученные результаты демонстрируют корректность настроек Router Advertisement, SLAAC, DHCPv6 и IPv6-маршрутизации.
